## 二、结论：当时这样换（v0.1 六件套；v0.2 已合并为五件套）

**原来的「需求分析（编号事实 R1–Rn）」拿掉，换成「需求池」。**理由：

- 课程 03 已经证明，用户画像之后最有用的产出不是一堆事实，而是一份**按 P0/P1/P2 排过序、每条都有验收方式**的需求池。
- 「需求调研」保留用户画像里的**人、场景、困难、现有办法、目标**；「需求池」承接**核心任务、完整过程、范围、取舍**。两者不重复。
- PRD 再往后接 04，线框图接 04，设计规范接 05，工作区接 06。一条线刚好对上课程顺序。

当时最终六件套（v0.2 已并成五件套，见 `templates/调研分析.md`）：

| # | 文件 | 来源 | 一句话 |
|---|---|---|---|
| 1 | `docs/需求调研.md` | 03 用户画像 | 帮谁、他卡在哪、现在怎么应付、想变成什么样 |
| 2 | `docs/需求池.md` | 03 需求池 | 第一版的核心任务、完整过程、P0/P1/P2 |
| 3 | `docs/PRD.md` | 04 PRD | 一版能照着做的方案，含“不做什么” |
| 4 | `docs/线框图.html` | 04 线框图 | 页面清单 + 主流程 + 灰框 |
| 5 | `docs/设计规范.md` | 05 设计规范 | 给 AI 读的颜色/字号/间距/组件规则 |
| 6 | `AGENTS.md` | 06 AGENTS | 目录、命令、回写约定 |

> 每份都同时有 `.md` 和 `.html`；HTML 是阅读版，MD 是源文。线框图的 HTML 就是它本身，另附一份 `.md` 页面清单。

## 三、逐份简化

### 3.1 需求调研.md（03 用户画像 → 5 块）

**课程里有**：认识这个人（项目名/称呼/身份/生活节奏/动机）、还原生活场景（环境/对象/限制）、困难与目标（每个困难三点）、事实与猜测（来源/待确认）。十几个字段 + 浏览器填写 + 导出。

**简化后**：

```markdown
# 需求调研 · [项目名]

> 来源：[项目创建时填写 / 访谈 / 观察]
> 还需要确认：[待验证的猜测]

## 1 这个人是谁
- 称呼与身份：
- 和这件事有关的生活节奏：
- 为什么在意这件事：

## 2 场景与限制
- 在什么环境里做：
- 涉及哪些对象，各有什么特点：
- 限制（时间/精力/经验/预算）：

## 3 困难、现有办法与目标
### 困难 1 · [一句话]
- 具体经历：什么时候、在哪、发生了什么
- 现在的办法：
- 想要的结果（用他的话，不写功能）：

## 4 事实与猜测
- 已知事实：
- 待验证假设：

## 5 这一版的范围
- 要帮的是：
- 不保证的是：
```

**砍掉**：星座式细节、HTML 填写器、localStorage、JSON 导入、案例“小林”。保留课程真正有用的骨架：人 → 场景 → 困难 → 现有办法 → 目标 → 事实/猜测。

### 3.2 需求池.md（03 需求池 → 4 块）

**课程里有**：产品与第一版范围（6 项）、优先级说明、每条需求的 8 个字段、21 条案例、HTML 工作表、P0/P1/P2 统计。

**简化后**（保留课程提示词 03 的骨架，只留一条占位需求）：

```markdown
# 需求池 · [项目名]

## 产品与第一版范围
### 项目名称
### 为谁服务
### 依据的用户资料
### 第一版的核心任务
### 完整使用过程
### 第一版范围与限制

## 优先级说明
P0：第一版必需；P1：后续改善；P2：留待考虑。

## 全部需求
### R01 · [需求名称]
优先级：P0
#### 对应什么困难
#### 用户希望达到什么结果
#### 准备怎么解决
#### 怎样检查完成
#### 为什么这样排序
#### 还需要确认什么

## 试用与验证计划
## 尚未确认的假设
```

**砍掉**：21 条案例、HTML 工作表、统计条、导出按钮。**保留**：核心任务 → 完整过程 → 范围 → 每条需求的问题/结果/解法/验收/优先级/理由/假设。这 8 个字段是课程最值钱的部分，不删。

### 3.3 PRD.md（04 的 10 节 → 6 节）

**课程 PRD 有 10 节、93 KB**：产品要解决什么、第一版范围、需求来源、产品基座、完整流程、页面与状态、信息与操作规则、验收场景、后续迭代、试用与决策。

**简化后 6 节**：

1. **这一版是什么**：一句话 / 帮助谁 / 场景任务 / 现在为什么不行 / 做成什么样 / 不做什么。
2. **范围与需求**：P0 编号与实现边界、已知风险。
3. **支撑第一版的基座**：入口与导航、信息对象及归属、空状态、输入校验、保存失败、纠错。
4. **页面与流程**：页面清单（对应线框图）、主流程、每页的进入条件/内容/按钮结果/空错成功。
5. **验收**：可操作的场景（保存后重开、修改归属、失败重试），第一版/后续分开。
6. **后续与待确认**：新增建议（不改需求池）、待确认、决策记录。

**砍掉**：逐页长文、案例页面细节、截图、plantlog 的具体规则。**保留**：范围锁定、P0 边界、基座、验收。默认让 AI 写 1–2 页，不写 90 KB。

### 3.4 线框图.html（04 的线框图 → 一页灰框）

**课程里有**：98 KB 的 HTML + JSON 页面数据 + 流程图 + 演示动效。

**简化后**：一张 HTML 里放：

- 页头：项目 / 版本 / 图例（灰框 = 未确认，实线 = 已确认）。
- 4–6 个手机框：首页 / 列表 / 详情 / 表单 /（按需）。
- 每个框：页面名、进入条件、主要内容块、主按钮、返回。
- 一条主流程箭头：从首页到完成再回来。
- 跨页面规则：空/加载/错误/未保存。

另附 `线框图.md`：页面清单 + 流程文字版，给 AI 读。

**砍掉**：JSON 编辑器、课程案例、演示动效。**保留**：页面清单、主流程、跨页规则。

### 3.5 设计规范.md（05 的 10 节 → 6 节）

**课程里有**：概览、颜色、字体、布局间距、层次、圆角、10 类组件、图标图片、该做不该做、待确认；32 KB，全部从 Demo 提取。

**简化后**：

1. **概览**：产品、用户、页面范围、3 个关键词。
2. **颜色**：bg / surface / ink / ink-2 / primary / line / error / success 八个 token + 使用规则。
3. **字体与间距**：字体族、字号层级、行高、间距、圆角、阴影。
4. **组件**：按钮、输入、单选、卡片、列表行、空状态、toast；每个写默认/悬停/焦点/禁用/错误。
5. **该做 / 不该做**：状态不能只靠颜色；不要另起色值。
6. **待确认**：AI 补的建议，标明“建议，待确认”。

**砍掉**：Demo 的具体像素值、案例组件、植物列表行、图片规则。**保留**：token、字号、间距、组件状态、禁令。

### 3.6 AGENTS.md（06 的 5 条 → 5 条）

课程模板只有 7 行，已经是很好的起点。插件版只改一处：**进度不指向 PLAN，指向 `.gd/project.json`**。

```markdown
# [项目名] · AGENTS.md

- 产品目标：[帮助谁完成什么；依据的需求文档路径]
- 当前状态：读 `.gd/project.json`，不在这里重复进度
- 目录：[docs 需求与设计] / [代码] / [资源]；启动见 README.md
- 开发节奏：先读 project.json 和当前任务相关文档；一次只做一个任务；不覆盖未完成改动
- 回写：结果、问题、下一步写 project.json；启动方式写 README；只有目标/目录/长期约定变化才改本文件
```

**PLAN.md 不进五件套。**课程用 PLAN 记进度；插件用 `project.json` + 版本卡记进度，再放一份 PLAN 会变成双真相。需要时由 AI 按需生成 PLAN（可选），不作为固定模板。

### 3.7 可选模板

| 模板 | 来源 | 为什么可选 | 简化后 |
|---|---|---|---|
| `docs/发布清单.md` | 07 上线流程 / 手机验收 | 小程序/网站/插件发布步骤不同，不强制 | 发布前（构建/真机/数据/备案）→ 发布后（线上打开/记录地址） |

| `验收记录.md` | 06 验收记录模板 | 人工验收才写，不预填 | 任务、操作、实际结果、通过/失败/未测 |

## 四、向导 → 模板的写入关系

新建向导只问 10 个字段，其中 5 个必填。它写进 `需求调研.md`，不直接生成需求池。

| 向导字段 | 必填 | 写到哪里 |
|---|---|---|
| 项目名 | 是 | `需求调研.md` 标题、`project.json.name` |
| 类型 | 否 | `project.json.kind` |
| 目录 | 是 | 生成位置 |
| 给谁用 | 是 | 需求调研 §1 |
| 这个人的背景 | 否 | 需求调研 §1 |
| 最麻烦的一件事 | 是 | 需求调研 §3 困难 1 的“具体经历” |
| 现在怎么应付 | 否 | 需求调研 §3 困难 1 的“现在的办法” |
| 想要的结果 | 否 | 需求调研 §3 困难 1 的“想要的结果” |
| 第一版核心任务 | 是 | 需求调研 §5、`project.json.version.goal` |
| 这一版不做什么 | 否 | 需求调研 §5、需求池“第一版范围与限制” |

向导创建后只做三件事：铺五件套模板、写一份填好的调研分析（§1–§5）、开新会话补全 §6 需求池。**不直接写 PRD/线框图/设计规范**。

## 五、不要原样搬的东西

- 课程案例的人物、植物、需求、页面、任务数量。
- 教辅里的 HTML 填写器、localStorage、导出/导入 JSON 按钮。
- 需求池的 21 条案例、P0 10 条的统计。
- PRD 的 90 KB 长文和逐页细节。
- 设计规范里 Demo 的具体色值和组件截图。
- 07 的 Vercel/GitHub 具体操作步骤（这些是课程内容，不是模板结构）。
- 08 的密钥和 API 调用（不把密钥写进项目文件）。
