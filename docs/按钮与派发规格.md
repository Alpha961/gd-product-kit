# gd-product-kit · 按钮与派发规格（Skill 契约）

> 版本：v0.1 ｜ 2026-11-13
> 用途：插件里每一个可点元素，点下去发生什么；凡是“派发 AI”的，写明提示词、目标工作区、上下文、产出和回写。
> 关系：**插件负责壳和按钮，Skill 负责被派发之后怎么干活。**本文是两者之间的合同，不是实现代码。

---

## 0. 先约定三个词

- **项目**：一个目录，根目录下有 `.gd/project.json`。
- **项目工作区**：这个目录在 DSH 里对应的 workspace。
- **派发**：把一段提示词发到“项目自己的工作区”的**新会话**里，让 AI 去干。

> **铁律：插件自己不调模型。** 需要生成、总结、补文件，一律派发给会话；插件只负责展示和把结果写回。

## 1. 动作分两类

| 类型 | 含义 | 例子 |
|---|---|---|
| **派发 D** | 新会话 + 提示词，AI 干活 | 继续做、派发待办、一键补充 |
| **本地 L** | 读写文件、开侧栏、探测 URL、打开目录 | 重新体检、升为待办、归档、复制路径 |
| **打开 O** | 在 DSH 侧栏或系统里打开内容 | 五件套、文档链接、发布地址 |

所有 D 类动作共用一个工作区解析和派发通道，见第 2 节。

---

## 2. 派发规则（所有 D 按钮共用）

### 2.1 目标工作区

1. 取**当前选中的项目**的目录 `path`（不是当前正在聊天的会话）。
2. 在 DSH 工作区列表里按规范化路径找：
   - 找到 → 直接用；
   - 找不到 → `createWorkspace({ path })` 建一个。
3. `connectWorkspace(workspaceId)` 开新会话。
4. 会话标题：`gd · <项目名> · <动作名>`。
5. `sessions.open(sessionId)` 跳到会话。

> 不派到当前会话；不切换用户当前的工作区；一个项目一个工作区。

### 2.2 上下文包

每次派发都带同一份“项目上下文”，prompt 里只给**路径和摘要**，不把全文贴进去：

- `.gd/project.json`
- 当前版本：label / state / goal / next
- 未完成待办、卡点
- 五件套路径（有的给路径，没有的标缺失）
- 关联文档（待办/点子各自的 `doc`）

### 2.3 回写

- AI 干完活，更新 `.gd/project.json` 对应字段（遵循项目内 `AGENTS.md` 的约定）。
- 插件每 5 秒轮询一次 `project.json`；也可以由“重新体检”手动刷新。
- AI 不能直接改的（比如发布地址），在结尾给“建议改哪些字段”，由人点“重新体检”确认。

### 2.4 禁用与防重复

- `archived`：所有 D 类和写入类按钮禁用，只读。
- `paused`：只允许“恢复并继续”；其它 D 类按钮先禁用，恢复后再用。
- 项目目录不存在：按钮禁用 + 提示“目录已移动”。
- 派发中：按钮 loading；同一动作 2 秒内不重复；失败不静默，toast + 保留会话入口。

## 4. 派发动作与提示词

> 下面所有 `{{...}}` 由插件填入；`<...>` 是说明，不进入 prompt。
> 每个 prompt 开头带动作标记，方便 Skill 路由和用户回看。

### D1｜新建项目 · 第一个会话（B35）

- **目标工作区**：新建项目目录（创建完成后）。
- **上下文**：向导已填的 `调研分析.md`（§1–§5）、新建的 `project.json`、`AGENTS.md`、§6 需求池空骨架。
- **提示词**：

```text
[gd-product-kit · new-project]
项目：{{name}}（{{kind}}）
目录：{{path}}
第一版核心任务：{{version.goal}}

先读 .gd/project.json、AGENTS.md、docs/调研分析.md。
调研分析 §1–§5 已经写了：给谁用、这个人的背景、最麻烦的一件事、现在怎么应付、想要的结果。
不要重复问这些；只问缺失的，最多 2 个问题。

任务：补全 docs/调研分析.md 的 §6 需求池：
1. 先概括用户、具体场景、困难、现有办法和目标；区分资料、推断和假设，不编造访谈。
2. 选定第一版核心任务，描述从开始到完成的完整过程；逐个检查添加、记录、查看、纠错、留存在本项目是否必要。
3. 再列需求：每条写问题、用户结果、解法、可检查的验收方式、优先级、理由和假设。P0 只放完成核心任务必需的，不要全是 P0。
4. 写清第一版范围、限制和试用计划。
只改 docs/调研分析.md 的 §6，不动 §1–§5；同时生成 docs/调研分析.html 阅读版。
不要写 PRD / 线框图 / 设计规范，不要改需求调研部分。
完成后更新 .gd/project.json 的 artifacts 和 next，并告诉我 P0 有几条、需要我拍板什么。
```

- **产出**：`docs/调研分析.md`（只改 §6）`/.html`；`project.json.artifacts` / `next` 更新。
- **UI 回写**：五件套「调研分析」变绿；`next` 显示在版本卡；P0 条数回到会话里由人确认。

### D2｜导入项目 · 补作业（B38）

- **目标工作区**：被导入项目目录。
- **上下文**：现有 `README`、`docs/`、版本记录、发布清单、点子池、`git log -30`。
- **提示词**：

```text
[gd-product-kit · import-backfill]
项目：{{name}}
目录：{{path}}

读现有材料：README、docs/ 下的文档、版本记录、发布清单、点子池、git log 最近 30 条。
把现状汇总成 .gd/project.json：
- name / kind / 一句话
- version：从版本记录或 package.json 推断；没有就 v0.1 + 构思
- release.url：从发布清单或 README 找
- artifacts：五件套对应路径；没有就 null
- todos / ideas：从点子池、TODO、发布清单提取，保留原文件链接
- next：根据最近提交和未完成项给一句建议
只写 .gd/project.json，不改任何已有文档。
最后用 10 行列出你的推断依据（哪一条来自哪个文件），等我确认。
```

- **产出**：`project.json` 初次生成；不生成/不修改五件套正文。
- **UI 回写**：项目卡、版本卡、待办、五件套状态出现；缺失项走“一键补充”。

### D3｜继续做 / 恢复并继续（B08）

- **目标工作区**：当前项目目录。
- **上下文**：版本、goal、next、未完成待办、卡点、五件套路径。
- **提示词**：

```text
[gd-product-kit · resume]
继续项目：{{name}}（{{path}}）
当前版本：{{version.label}} · {{version.state}}
版本目标：{{version.goal}}
下一步：{{version.next}}
未完成待办：{{todos}}
卡点：{{blockers}}
五件套：{{artifact paths}}

先读 .gd/project.json 和相关文档，用 5 行以内回答：
1. 现在卡在哪；
2. 建议先做哪一件；
3. 需要我拍板什么。
我确认后再动手；不要一次改多个文件。
```

- **暂停项目**：先本地写 `state=开发中`，再派发同一 prompt。
- **产出**：先判断，不直接改文件；用户确认后再执行。

### D4｜派发一条待办（B12）

- **目标工作区**：当前项目目录。
- **上下文**：这条待办、所属版本、关联文档。
- **提示词**：

```text
[gd-product-kit · todo]
项目：{{name}}（{{path}}）
执行待办：{{todo.title}}
所属版本：{{version.label}} · {{version.state}}
版本目标：{{version.goal}}
关联文档：{{todo.doc}}

先读 .gd/project.json 和关联文档，然后：
1. 复述你理解的验收标准（3 行内）；
2. 列改动清单（文件级）；
3. 我确认后再改；完成后更新 project.json 里这条待办的状态和 next。
不要顺手做其它待办。
```

- **产出**：待办状态 `todo → doing → done`；需要文档变更的，同步更新。
- **UI 回写**：派发后按钮 loading；`project.json.todos[]` 更新后卡片变色。

### D5｜一键补充（B11）

- **目标工作区**：当前项目目录。
- **上下文**：缺失清单（文件 + 缺 md/html），已有文件不动。
- **提示词**：

```text
[gd-product-kit · fill-artifacts]
项目：{{name}}（{{path}}）
当前版本：{{version.label}} · {{version.state}}
缺失清单：{{list：文件 + 缺 md / html}}

按模板补齐，不覆盖已有内容：
- 缺 md：从现有文档 / git / 代码里提取，找不到依据的段落写「TODO: 待补」；
- 缺 html：把同名 md 生成 HTML 阅读版，套 templates/artifact.html；
- 每份产出同时保留 .md 和 .html。

完成后更新 .gd/project.json 的 artifacts，并列出补了哪些、哪些留 TODO。
```

- **产出**：缺失文件；`project.json.artifacts` 更新。
- **UI 回写**：绿色标签出现；体检里的计数变绿。

### D6｜生成单份产出（B30，两份都缺）

- **目标工作区**：当前项目目录。
- **上下文**：该产出在项目里的相关文件（PRD、线框图、规范等）。
- **提示词**：

```text
[gd-product-kit · artifact]
项目：{{name}}（{{path}}）
产出：{{artifact.title}}
输出：docs/{{file}}.md 和 docs/{{file}}.html
依据：{{related files}}

按 templates/{{file}}.md 的结构写，同时产出 HTML 阅读版（套 templates/artifact.html）。
不要编造；找不到依据的段落写「TODO: 待补」。
完成后更新 .gd/project.json 的 artifacts 和 next。
```

### D7｜把 MD 生成 HTML（B30，只有 MD）

- **目标工作区**：当前项目目录。
- **提示词**：

```text
[gd-product-kit · artifact-html]
项目：{{name}}（{{path}}）
把 docs/{{file}}.md 生成 docs/{{file}}.html。
要求：套 templates/artifact.html；保留标题层级、表格、代码块；相对链接不改；内容以 md 为准。
只做这一份，不改 md，不改其它文件。
```

### D8｜数据过期 · 回顾（B21）

- **目标工作区**：当前项目目录。
- **提示词**：

```text
[gd-product-kit · review-stale]
项目：{{name}}（{{path}}）
.gd/project.json 最后更新：{{updatedAt}}；之后有 {{n}} 条提交。

读 project.json、git log（since {{updatedAt}}）、最近会话标题，给一份 10 行以内的更新建议：
- 哪些待办已经完成；
- 哪些提交没有记进版本；
- next 应该改成什么。
先只给建议，不要写 project.json；我确认后再更新。
```

## 5. 本地动作的写入点

| 按钮 | 读什么 | 写什么 | 失败/边界 |
|---|---|---|---|
| B06 重新扫描 | 配置的根目录 | 不写项目文件；只更新插件 registry | 目录不存在 → 提示 |
| B13 添加待办 | `project.json` | `todos[]` 追加一条 | 空标题不提交 |
| B15 升为待办 | 点子原文 | `todos[]` 追加；不删点子 | 已存在同标题 → 提示 |
| B18 重新体检 | `project.json`、五件套、git、发布地址 | 不写；只刷新 UI | 地址超时 5 秒 |
| B19 归档 / 取消归档 | `project.json` | `archived` | 归档后所有派发禁用 |
| B20 恢复项目 | `project.json` | `state=开发中` | — |
| B22 重新检测 | 发布地址 | 不写；只更新内存里的体检结果 | HTTP 失败 = 打不开 |
| B23 铺模板 | 插件 templates | 只补缺的文件，不覆盖 | 同名文件跳过并报告 |
| B31–B35 新建 | 用户输入 | 目录、`project.json`、五件套、`AGENTS.md` | 目录非空 → 提示 |
| B36–B40 导入 | 根目录 | registry + 可选 `project.json` | 路径重复 → 跳过 |
| B09 打开目录 / 复制路径 / 打开 project.json | — | 不写 | 系统不支持 → 提示 |

> “重新体检”不写 `project.json`，避免体检结果和真相混在一起；页面上的绿点/计数都是每次重算的。

## 10. v1 实现备注（2026-11-13）

- **五件套打开方式**：v1 用面板内 480px 抽屉（HTML 阅读版 / MD 源文 / 在 DSH 侧栏打开）。全局面板下 `sidebarRight.openResource` 会报 `no session surface is mounted`，所以 DSH 右侧栏只在会话表面挂载时可用。
- **派发已验证**：`workspaces.create`（没有工作区时）→ `uiWorkspace.connectWorkspace` → `sessions.retain` → `binding.session.prompt` → `uiWorkspace.openSession`。会话标题 `gd · 项目名 · 动作名`。
- **导入**：v1 用「导入项目」模态：扫描 `E:\AI` / `E:\WORK`，勾选导入；没有 project.json 的项目点「补作业」派发 D2。导入选中只登记，不派发。

- **本地写操作**：添加待办已换成内联表单（标题 + 保存/取消）；归档/恢复换成正式确认弹窗（危险操作用红色按钮）。
- **HTML 阅读版**：抽屉里注入 artifact HTML；`img[src]` / `<link>` / `srcset` / `<style>` / `style` 属性的相对路径重写到宿主 `/files` 路由；本地 `<link rel="stylesheet">` 会被拉取内联，CSS `url()` 按 CSS 文件目录重写。CSS `@import` 还没处理。
- **Skill 安装**：`skills/gd-product-kit` 已复制到 `~/.dsh/skills/gd-product-kit`，模板也一起复制；新会话可读到。
